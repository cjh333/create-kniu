## 反馈管理排序不落库（根因+修复+回归）

**现象**：反馈管理表格内改 sid 数字，界面值变了但刷新后还原。

**根因（两层）**：
1. usePage `field:'id',sort:'desc'` → 刷新后按 id 排序，掩盖 sid 变更（已改 `field:'sid',sort:'asc'`）。
2. 🔴 **kniu-table editable 列 onChange 恒失效**：模板引擎对自定义组件（tag 含 `-` 且 `'options' in node`）走 `node.options = mergedValue`（kniutemplate.mjs:981-983），**不写 `__kniuOptionsValue`**；kniu-table.mjs `_readColumns` 的 onChange 包装器只读 `element.__kniuOptionsValue?.onChange` → 恒 undefined → `return true` → beginCellEdit 视为保存成功，仅本地保存不发请求。editable 生效是因 options setter 的 reflectOptions 把非函数值反射成 attribute（editable="number"），函数值被跳过（2429 行）。

**修复**：
- `client/views/admin/feedback.html`：sid 列 `:option` 补 `onChange:(updateSort)`（对齐 user.html 昵称列先例）。
- `client/core/kniuui/kniu-table/kniu-table.mjs`：onChange 包装器回退链加 `element.options?.onChange`（兼容 options-only 注入路径），`__kniuOptionsValue` 路径保留在首位。

**回归（真机 agent-browser）**：点击 sid 单元格 → 编辑态 input → 改 1 → Enter/blur → /feedback_update 请求发出（HTTP 200）→ 刷新后 sid=1 保持、列表正常。进入编辑态的事件序列：pointerdown + **click**（handleBodyClick 是进入编辑的唯一入口；pointerdown 只负责已有 input 时先 blur）。

**连带发现（未改，待用户决策）**：article/comment/daily/database 四页 sid 列均无 onChange，排序编辑同样只本地保存不落库；user.html 昵称列（onChange:(updateNickname)）此前也因同一根因失效，本次修复后恢复真正落库。

### 追加：改 sid 整表闪烁（根因+修复+回归）

**现象**：改一次 sid，整表明显「闪一下」。

**根因**：保存 sid 后 loadList 重拉走**非 silent 路径**——`state.loading=true` → syncOptions 替换 state[tableKey] → kniu-table options setter → `setLoading(true)` → `.kniu_sys_table_loading[data-active=true]` 遮罩（rgba(255,255,255,.9) 近白全表层 + 34px spinner + 「加载中」文字）盖住整表，停留时长=请求时长。本地请求 62ms，用户机器 PHP 冷启动几百 ms 时即「明显闪一下」。行 DOM 本身零重建（rowPool 复用），闪烁全部来自遮罩。

**测量方法（配对 A/B，monkey-patch 法）**：
- rAF 轮询/MutationObserver 直接观测遮罩节点会假阴性（12-62ms 窗口 + 节点替换疑云），**不可靠**；

- 顺带证实数据通道活着：setter 调用时 rows 随请求结果变化（搜索无匹配 rows:0），setData 照常同步。

- 四控制器 updateSort 重拉改 `loadList(state.currentPage, { silent: true })`（feedback/article/comment/daily）。
- 「按 sid 排序刷新」语义不变（服务端数据仍回表），只是不再弹遮罩。
