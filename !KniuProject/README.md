# AI 记忆文件部署与维护说明

> 这套文件解决一个问题：**「写了规则还是重复犯错」**。
> 根因通常不是规则写得不够多，而是：文件没被读到 / 写得不可执行 / 硬约束没落到强制执行。
> 本说明告诉你每份文件放哪、怎么验证真的生效、哪些必须下沉到权限或钩子。
>
> **本说明与任何特定 AI 工具无关**，适用于所有具备记忆文件机制的 AI 编程助手。
> 文中 `<用户记忆目录>` 泛指所用 AI 的用户级记忆目录（各工具命名不同，以其实际约定为准）；
> `<项目记忆目录>` 泛指项目内的记忆目录。实际路径对照统一收敛在全局层 `MEMORY.md` 的「记忆位置」一节，其他文件只引用逻辑位置。

---

## 一、四份文件分别放哪

| 文件 | 放到哪里 | 作用域 | 说明 |
|---|---|---|---|
| `SOUL.md` | `<用户记忆目录>/SOUL.md` | 全局，所有项目 | **主规则文件**。每次会话最先被读，放身份、边界、红线、防重复机制 |
| `MEMORY.md` | `<用户记忆目录>/MEMORY.md` | 全局，跨项目 | 跨项目长期偏好 + **经验库** + 规则变更记录 |
| `项目级-记忆模板/MEMORY.md` | `<项目记忆目录>/MEMORY.md` | 仅该项目 | 项目约定 + 本项目经验库；每个项目复制一份 |
| 每日日志 `YYYY-MM-DD.md` | `<项目记忆目录>/` | 仅该项目 | 每天一份，只追加；**只保留近 3 天**，更早的提炼进 MEMORY.md 后删除 |

**优先级（打架时听谁的）**：本次对话指令 > 项目级 > 全局（SOUL/MEMORY）> 云端画像。
`SOUL.md` 里已写明这条裁决规则，并加了「以本次对话为准」的兜底，防止某次正式任务被全局偏好带偏。

## 二、怎么确认「真的生效了」（关键，别跳过）

1. **开一个全新会话**（旧会话仍用旧上下文，改了文件也不刷新）。
2. 用工具自带的上下文/记忆查看入口，确认本次会话**实际加载了** `SOUL.md`、全局 `MEMORY.md`、项目 `MEMORY.md`。
   - 若目标文件不在列表 → 问题在**位置或作用域**，先修正路径。
   - 若在列表里却不遵守 → 才进入**内容质量**排查（见第三节）。
3. 给它一个能检验规则的小任务（例：「这个项目该跑哪条测试命令？」），看回答是否引用了正确规则。

## 三、为什么之前写了还是重复犯错 —— 逐条对照

| 现象 | 真实原因 | 本套文件的解法 |
|---|---|---|
| 文件在，但 AI 没照做 | 位置错 / 被截断 / 旧会话没刷新 | 明确路径 + 验证步骤（第二节） |
| 规则写了等于没写 | 写成「注意质量」这类口号 | 统一改成「触发条件 + 具体动作 + 检查标准」 |
| 你最在意的那条被忽略 | 文件太长，条数越多每条遵守率越低 | `SOUL.md` 硬上限 200 行，只留会做错的 |
| 换项目就打架 | 全局与项目规则冲突 | 明确优先级 + 冲突裁决条款 |
| 禁区还是被碰 | 规则是「建议」，不是「强制」 | 红线**同时下沉到权限/钩子**（第四节） |
| 经验换个会话就断 | 只存了对话，没落盘 | 出错当轮即写「经验库」条目 |

## 四、必须下沉到权限 / 钩子的硬约束（不能只靠文件）

规则分三类，各归其位：

| 类型 | 例子 | 放哪 | 原因 |
|---|---|---|---|
| 软规范 | 命名风格、模块划分、技术栈约定 | 记忆文件 | 需语义判断，适合让模型判断 |
| **边界规则** | 禁止删目录、禁止改 lockfile、禁止外发密钥 | **权限设置** | 必须确定性执行，靠自觉拦不住 |
| **流程规则** | 提交前必须跑测试、改动后更新文档 | **钩子（事件触发）** | 有明确条件，适合程序化拦截 |

## 五、日常维护（把规则当代码养）

- **规则即代码**：命令或流程改了，**同一次修改里**顺手更新对应规则文件。一条跑不通的命令，会让 AI 从此不信任这份文件。
- **每月复查**：删过期项、合并重复项、检查全局与项目是否冲突（例：已从 npm 迁到 pnpm，旧的全局偏好还在制造冲突）。
- **换工具/换设备**：经验放在与工具解耦的层级（本套的记忆文件），不要散落在各工具各自的规则里。
- **多设备同步**：可用云盘或私有 Git 仓库同步 `<用户记忆目录>` 下的记忆与身份文件。
- **隐私分级**：技术方法可放公开文档；个人偏好、凭证规则只在本地 `<用户记忆目录>`，不进任何要发布的内容。

## 六、落地顺序建议

1. 先把 `SOUL.md` 放进 `<用户记忆目录>`，开新会话验证能被读到。
2. 把 `MEMORY.md` 放进 `<用户记忆目录>`，先只填「我是谁 / 长期偏好」两节。
3. 挑**一个最常重复犯错的项目**，复制项目模板，把它踩过的坑写成第一批经验条目。
4. 对照第四节，把红线落到权限设置里。
5. 设一个每月的复查提醒，按第五节维护。
