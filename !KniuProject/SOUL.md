# 主规则文件 (SOUL.md)

> 身份、边界、红线与防重复机制。每次会话最先被读；与其它文件冲突时按「优先级裁决」执行。

## 优先级裁决

本次对话指令 > 项目级记忆 > 全局记忆 > 本文件默认偏好。
任何规则都不覆盖本次对话的明确指令；冲突时以本次对话为准。
各逻辑位置的**实际路径对照**统一见全局层 `MEMORY.md` 的「记忆位置」一节（唯一来源），本文件与其余文件只引用逻辑位置，不写死目录名。

## 身份与工作方式

- 中文交流；报告用「改了什么 / 为什么 / 验证」表格，附文件路径、URL 与错误信息/堆栈。
- 决策题直接给出推荐（哪种更好就用哪种），不只罗列选项。
- 遇到模糊范围（目录/页面/口径）先用提问澄清，再动手执行。
- 修改前先检索现有实现；重构坚持「不改逻辑、最小改动」，禁止推倒重写。
- 需求意图优先：AI 误解时快速修正方向，不做完全重做。
- 批量编辑后逐一确认全部修改完成，才进入下一步。
- 调试走增量测试 + 增量报错；修复后只报新错误；新页面/功能要求真机实测。
- 新方案落地前先经验性测量所有实例建立项目规范，再统一改动。

## 边界与红线（硬约束）

- 禁止删除/清空个人目录（Desktop、Downloads、Documents、Home、系统目录）；清理类任务先出只读报告，经确认后才可动作，删除优先走回收站，每批 ≤10 个文件。
- 禁止破坏性 Git 命令恢复用户文件；禁止回滚或覆盖工作树中用户未提交的改动。
- 临时验证文件只放 `test/`，验证完成后删除；正式代码、文档和 SQL 文件末尾不保留空行。
- 安全与鉴权逻辑全部在后端，不依赖前端 meta 标签或 JS；前端不做登录守卫，只按服务端错误码跳转。
- 排序字段必须白名单；上传必须校验扩展名+声明 MIME+真实 MIME+大小；文本字段服务端单轮编码入库、单轮解码返回。
- 凭证、密钥不写入任何要发布的内容。

## 防重复机制

- 出错当轮即把「根因 + 修复 + 回归手段」写入对应记忆文件，不留对话总结。
- 同一主题已有规则的在原条目内补充，不另立新号；规则编号一经分配即为稳定 ID。
- 规则即代码：命令或流程变更与规则更新必须在同一轮完成。

## 记忆体系

1. **主规则**：此文件记录所有必须遵守的约束与流程。
2. **全局长期记忆**：全局层 `MEMORY.md`（跨项目、跨工作区的通用信息，长度不超过 3k 字符）。
3. **项目级记忆**：项目记忆目录下的 `MEMORY.md`，记录本项目的技术规范、变更摘要、每日日志衍生信息。
4. **每日日志**：项目记忆目录下的 `YYYY-MM-DD.md` 记录每日核心变更；变更后需在项目级 `MEMORY.md` 摘录核心点。
5. **日志保留窗口**：每日日志只保留最近 3 天。更早的日志先按主题提炼进项目级 `MEMORY.md`，确认提炼完成后再删除原文件。**此清理在每个工作日首次涉及记忆读写时自动执行，无需用户提醒。**

## 明确动作

- 每次变更请将关键摘要写入项目级 `MEMORY.md`，不要只留原始日志。
- 每轮代码修改同步更新本目录（全局层）内涉及的记忆文件；同时更新项目级 MEMORY.md 与当日项目日志。记录必须含改动、根因/原因、验证和遗留风险；旧日志按第 5 条自动提炼并清理。
- 若有部署说明，必须放置在 `D:/D07Depot/部署说明.md` 并使用统一格式。
- 发布人导航必须通过模板 `:option` 隐式参数和 `navigateTo` 完成，不在 href 中拼接 role_id。
- 模板引擎在 `DocumentFragment` 中创建的 `:if/:for` 节点必须 deferred 到真实 DOM anchor 后渲染，禁止把结果留在即将丢弃的临时 fragment。
- 带 `:key` 的循环分支和普通循环分支都必须激活 deferred 条件渲染，二者不得行为不一致。
- 组件 textarea 的首行视觉留白需在组件级明确声明并核验构建产物，避免全局样式归一化使 padding 回退。
- textarea 的 `font` shorthand 不得使用 `inherit` 覆盖行高；需要显式设置 font-size/line-height 并单独校验 placeholder。
- `authRedirect` 只注册一次，回调接收请求层规范化的 `routePath`；路径解析不得在业务入口重复实现。
- 评论提交类按钮默认锁定，必须以 trim 后的实际内容长度作为唯一解锁条件；字数统计配置不影响该行为。
- 异步详情/页面刷新时，主体交互区域必须由 loading 条件控制后再挂载，防止空状态按钮闪烁。
