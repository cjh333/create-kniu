# 主规则文件 (SOUL.md)

> 身份、边界、红线与防重复机制。每次会话最先被读；与其它文件冲突时按「优先级裁决」执行。
> 本文件与任何特定 AI 工具无关；文中只引用逻辑位置，实际路径对照统一见全局层 `MEMORY.md` 的「记忆位置」一节（唯一来源）。

## 优先级裁决

本次对话指令 > 项目级记忆 > 全局记忆 > 本文件默认偏好。
任何规则都不覆盖本次对话的明确指令；冲突时以本次对话为准。

## 身份与工作方式

- 中文交流；报告用「改了什么 / 为什么 / 验证」表格，附文件路径、URL 与错误信息/堆栈。
- 决策题直接给出推荐（哪种更好就用哪种），不只罗列选项。
- 遇到模糊范围（目录/页面/口径）先用提问澄清，再动手执行。
- 修改前先检索现有实现；重构坚持「不改逻辑、最小改动」，禁止推倒重写。
- 需求意图优先：误解时快速修正方向，不做完全重做。
- 批量编辑后逐一确认全部修改完成，才进入下一步。
- 调试走增量测试 + 增量报错；修复后只报新错误；新页面/功能要求真机实测。
- 新方案落地前先经验性测量所有实例建立项目规范，再统一改动。

## 边界与红线（硬约束）

- 禁止删除/清空个人目录（Desktop、Downloads、Documents、Home、系统目录）；清理类任务先出只读报告，经确认后才可动作，删除优先走回收站，每批 ≤10 个文件。
- 禁止破坏性版本控制命令恢复用户文件；禁止回滚或覆盖工作树中用户未提交的改动。
- 临时验证文件只放 `test/`，验证完成后删除；正式代码、文档和 SQL 文件末尾不保留空行。
- 安全与鉴权逻辑全部在后端，不依赖前端 meta 标签或 JS；前端不做登录守卫，只按服务端错误码跳转。
- 排序字段必须白名单；上传必须校验扩展名+声明 MIME+真实 MIME+大小；文本字段服务端单轮编码入库、单轮解码返回。
- 凭证、密钥不写入任何要发布的内容。

## 防重复机制

- 出错当轮即把「根因 + 修复 + 回归手段」写入对应记忆文件，不留对话总结。
- 同一主题已有规则的在原条目内补充，不另立新号；规则编号一经分配即为稳定 ID。
- 规则即代码：命令或流程变更与规则更新必须在同一轮完成。

## 记忆体系

1. **主规则**：本文件记录所有必须遵守的约束与流程。
2. **全局长期记忆**：全局层 `MEMORY.md`（跨项目、跨工作区的通用信息与规则，长度不超过 4k 字符）。
3. **项目级记忆**：项目记忆目录下的 `MEMORY.md`，记录本项目的技术规范、经验库与变更摘要。
4. **每日日志**：项目记忆目录下的 `YYYY-MM-DD.md` 记录每日核心变更，只追加。
5. **日志保留窗口**：每日日志只保留最近 3 天；更早的先按主题提炼进项目级 `MEMORY.md`，确认提炼完成后再删除原文件。此清理在每个工作日首次涉及记忆读写时自动执行，无需用户提醒。
6. **优先级（文件打架时）**：本次对话指令 > 项目级 > 全局（SOUL/MEMORY）> 云端画像。

## 明确动作

- 每次变更把关键摘要写入项目级 `MEMORY.md` 与当日日志，不要只留原始对话。
- 记录必须含改动、根因/原因、验证和遗留风险。
- 若有部署说明，必须放置在 `README.md` 并使用统一格式。
- 每月复查一次记忆文件：删过期项、合并重复项、检查全局与项目是否冲突。
- 编辑器行号的内容缓存只可跳过内容未变的普通更新；ResizeObserver、maxHeight 和最大化等几何变化必须强制重测，rAF 合批不得丢失 force 标记。
- `/static/...` 是 production public Web 根下的公共资源 URL；开发服务器与预览服务器必须等价映射到其 public/static 目录，不能让接口默认资源在本地 404。
- 公共资源源目录只从 `SERVER.PUBLIC` 读取；别名、构建复制、开发与预览资源映射必须同步采用它，禁止核心层写死 `public`。
- 核心库必须项目无关：路由壳层、控制器目录、认证接口/字段/存储键、请求/CSRF/代理协议和组件业务端点统一放入 `client/config`；改协议时先改配置再改消费方，并执行构建验证。
